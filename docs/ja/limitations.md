# ⚠️ 制約と適用範囲

現行の SpriteStudio Player for Unity でアプリを配信する際に把握しておくべき制約と注意点をまとめています。対応している機能については [ドキュメント目次](./index.md#主な機能-key-features) の「主な機能」および各ワークフローガイドを参照してください。

## 未実装の機能

> [!WARNING]
> - **テキストパーツ** — 描画されません。ランタイムは描画プラン上の位置を確保しますが、グリフは提供しません（グリフのレイアウトとラスタライズは Player 側の責務です）。本プラグインには Unity でのテキスト描画パスがまだありません。
> - **9 スライスパーツ** — 描画されません。ランタイムはグリッド全体を専用の `Nines` バッファに構築しますが、本プラグインはまだそれを読んでいないため、セルが引き伸ばされた状態ではなく何も表示されません。
> - **シーケンス（`.ssqb`）の再生** — 未対応です。ファイルは `SpriteStudioSequenceAsset` としてインポートされます。アニメーションを続けて再生するには `OnAnimationFinished` で切り替えてください（[SSAB と SSQB の使い分け](./workflow/tips.md) 参照）。

テキストパーツと 9 スライスパーツは描画順序上の位置を保持するため、これらを使ったアニメーションはエラーにならず、該当パーツが欠けた状態で再生されます。出荷するアニメーションでは、作画時に通常パーツへ置き換えてください。

## Canvas（uGUI）パス

`SpriteStudioGraphic` は CanvasRenderer の「1 レンダラー = 1 メッシュ + 1 マテリアル」という制約に合わせて実装されているため、ワールドパス（`SpriteStudioPlayer`）では不要な次の制約があります。詳細は [パフォーマンスチューニングと高度な設定](./workflow/tips.md) を参照してください。

> [!WARNING]
> - **単一アトラス前提。** 複数アトラスを使うアニメーションでは最初のアトラスのみが描画され、他のアトラスのパーツは正しいテクスチャを参照できません（警告がログ出力されます）。アトラスを 1 枚にまとめるか、ワールドパスを使用してください。
> - **ブレンドモードは MIX / ADD のみ。** シェーダー内で頂点単位に振り分けており、それ以外のブレンドはすべて MIX に集約されます。
> - **`TexCoord1` と `TexCoord2` が自動的に有効化されます。** パーツカラーを TEXCOORD1 と TEXCOORD2 で渡すため、対象 Canvas の `additionalShaderChannels` に両方が自動追加されます。
> - **メッシュエフェクトとパーツ単位のシェーダは効きません。** グラフィックは `OnPopulateMesh` を通さずに自らメッシュを渡すため、付けた `Shadow`・`Outline` などの `BaseMeshEffect` は何も変えません。またパーツ単位の AddOn / カスタムシェーダ（セピア・アウトライン・ブラーなど）は Canvas では描画されず、すべてのパーツが 1 つの Canvas 用マテリアルで描画されます。
> - **SpriteStudio のマスクは効きません。** グラフィックはステンシルのマスクを書き込みも判定もしません。マスク専用のパーツは何も描かず、ほかのパーツはマスクなしで描かれるため、マスクで隠すはずのものが見えます。切り抜きは uGUI の **Mask** / **Rect Mask 2D** で行ってください（[パフォーマンスチューニングと高度な設定](./workflow/tips.md#マスク--クリッピング)）。
> - **Timeline からは制御できません。** `SpriteStudioGraphic` は `ITimeControl` を実装しておらず、Timeline のトラックが結び付けられるのは `SpriteStudioPlayer` だけです。

複雑なブレンドや複数アトラスが必要な場合は、ワールドパス（`SpriteStudioPlayer`）を使用してください。ワールドパスは「2」付きの種別のうち 2 つを除くすべてのブレンドを描画します。**Mul2** は Mul、**Screen2** は Screen として描画し、パーツの背後の色を必要とする **Div2** と **Overlay2** は MIX として描画します。

## マスク / クリッピング

この節はワールドパス（`SpriteStudioPlayer`）の話です。Canvas パスは SpriteStudio のマスクを使いません。ステンシルバッファのうち本プラグインが使用するのは、URP がユーザーに開放している下位 4 ビットだけです（それ以外のビットはライトやマテリアル種別に使われており、侵すと描画が壊れます）。この 4 ビットを「マスク影響」の有無で 2 つに分けて使うため、片方に重ね合わせの上限があります。

> [!NOTE]
> - **「マスク影響」がオフのマスクは、同一ピクセル上で 7 枚までです。** 8 枚目が重なるとその画素の計数が一周し、マスクが外れて見えます。
> - **「マスク影響」がオンのマスクに枚数の制限はありません。** 反転（奇偶）で処理されるためです。
>
> インスタンスの中のマスクは、自分とそれを描くインスタンスパーツのどちらかで「マスク影響」がオフなら、オフのマスクとして数えます。インスタンスの中のクリッピングはアニメーション全体の描画の最後まで効くので、そのインスタンスより後に描かれるマスクとも重なります。
>
> 上限に達するのは「同一の描画スコープ内で、同じ画素の上に、マスク影響オフのマスクが 8 枚以上重なる」場合だけです。通常のアニメーションでこの状態になることはまずありません。該当した場合は、マスクを統合するか「マスク影響」の設定を見直してください。

## パーツトラッキング

パーツトラッキング（`Transform` をパーツに追従させる機能）は `SpriteStudioPlayer`（ワールド）専用で、`SpriteStudioGraphic`（Canvas）にはありません。詳細は [スクリプト制御とイベント](./workflow/usage_scripting.md) を参照してください。

> [!NOTE]
> **メッシュ（スキン）パーツには直接追従できません。** 頂点はボーンのスキニングで描かれる一方、パーツ自身の変換はセットアップ時のノード位置（多くはキャラクターのルート付近）に留まるため、そのパーツを指定すると追従先は見た目の絵ではなくルート付近に吸い寄せられます。SpriteStudio 側でその位置に **NULL／ボーン／ジョイントパーツ** を置き、そのパーツを追従先に指定してください。

## エディタとインポート

> [!WARNING]
> - **`Open SSPJ` には SpriteStudio 本体が必要です。** OS のファイル関連付け経由でエディタを起動するため、作業する PC に [SpriteStudio](https://www.webtech.co.jp/spritestudio/) がインストールされている必要があります。`.ssab` ↔ `.sspj` の紐付け自体は `ProjectSettings/SpriteStudioSourceMap.json` に相対パスで保存され、プロジェクトと一緒に共有されます（[アセットのインポートとエディタ連携](./workflow/usage_asset_pipeline.md)）。

> [!NOTE]
> - **編集モードでは開始フレームの静止プレビューのみ表示されます。** 動作確認は再生モードで行ってください。
> - **Mesh Renderer の Materials はプレイヤーが管理します。** 描画するものが変わるたびに、プレイヤーが描画バッチごとに 1 つずつマテリアルを並べ直すため、リストに入れたマテリアルは置き換わります。描き方を変えたいときは、アトラステクスチャの隣にある共有 `.mat` を編集するか、パーツ単位のシェーダならプレイヤーに **Shader Catalog** を持たせてください（[パフォーマンスチューニングと高度な設定](./workflow/tips.md) 参照）。

## スクリプト API

> [!NOTE]
> - **`Play()` は先頭に巻き戻ります。** 現在フレームから再開するには、`Pause()` でフレームを保持し `Resume()` で解除してください。`Play()` は再開用途には使えません。
> - **シグナルはマネージド文字列を生成します。** Tick とメッシュ構築のループはゼロアロケーションで、数値のシグナルパラメータも再利用可能な型付きバッファへデコードされますが、パーツ名・コマンド ID・文字列型パラメータはマネージド文字列として実体化する必要があります。そのためシグナルを大量に、あるいは高頻度で発火するアニメーションでは、モバイル／WebGL で軽微なヒッチが生じることがあります。
> - **プレイヤーはスケールされた時間で進みます。** すべてのプレイヤーは `Time.deltaTime` で進むため、ポーズメニューなどで `Time.timeScale = 0` にすると、そのメニューの UI のアニメーションも止まります。スケールされない時間で進める設定はまだありません。

## モーションブレンド

> [!WARNING]
> - **インスタンスパーツとエフェクトパーツはモーションブレンドの対象外です。** これらは 1 つのアニメーションではなく `.ssab` 全体のものなので、track 0 のクロスフェードでは準備し直さず、動いているまま引き継ぎます。切り替えの前後でどちらのキーがそのパーツを動かすかは混ぜられません。両方のアニメーションが同じフレームにキーを持つ場合、出ていく側のキーの設定のまま動き続けることがあります。
> - **Timeline が動かしているプレーヤではブレンドされません。** クリップはプレーヤを進めずにシークするため、フェードや重ねたトラックは止まったままになり、track 0 は、SpriteStudio Track のクリップが自分のアニメーションに戻します。

## Timeline

`SpriteStudioTrack` や Control Track は、`SpriteStudioPlayer` を進めるのではなくクリップのフレームへシークして動かします。そのため、クリップが動かしている間のプレイヤーには次の制約があります。[Timeline からの駆動](./workflow/usage_scripting.md#timeline-からの駆動) も参照してください。

> [!WARNING]
> - **イベントもサウンドも出ません。** クリップがプレイヤーを動かしている間は、再生モードでも `UserData` / `Signal` / `Audio` のイベントは発火せず、組み込みのサウンドも鳴りません。`OnAnimationFinished` と `OnAnimationLooped` も発火しません。
> - **ループ・ピンポン・逆再生は効きません。** クリップの時刻はアニメーションの区間内に収めたフレームになるため、クリップの下では、ループするアニメーションも 1 回再生して最終フレームで止まります。
> - **`SpriteStudioTrack` のクリップはアニメーションの長さを知りません。** クリップは Timeline の既定の長さで置かれるため Match Content で長さを合わせられず、Clip In・Speed Multiplier・Looping も使えません。**Animation Name** は自由入力です。
> - **編集モードでスクラブしても動きません。** 編集モードのプレビューは開始フレームのままなので、カットシーンは再生モードで確認してください。

## エフェクト

> [!NOTE]
> - **同じアセットのプレイヤーは同じパーティクルを描きます。** エフェクトパーツの乱数シードはプレイヤーではなくパーツとエフェクトから決まるため、同じ `.ssab` から作ったプレイヤーを並べると、まったく同じパターンで発生します。

## 再生機能の制約

最初の 3 つは共通コア `libssruntime` に由来するため、描画パスとプラットフォームを問わず、すべての公式 Player に共通します。詳しい説明と、その他の共通制約（embedded モード、`.ssab` の入力検証を行わない件など）はポータルにまとめてあります: **[共通の制限事項](https://cri-middleware.github.io/SpriteStudio-Docs/ja/sdk/limitations/)**。最後の 1 つは WebGL ビルド固有です。

> [!WARNING]
> - **`independent=true` のパーツ（インスタンス／エフェクト）は逆再生・シークで正しく動作しません。** 正しいのは順方向の再生（順方向のフレームスキップを含む）のみです。
> - **シークは通過したフレームのイベントを発火しません。** 発火するのは移動先フレームの `UserData` / `Signal` / `Audio` のみです。
> - **オーディオは逆再生できません。** 実質的な進行方向が逆向き（逆再生、ピンポンの復路）の場合、サウンドはスキップされます。負の再生速度はこれに該当しません。速度は倍率であり、負値は再生ヘッドの向きを変えるのではなく停止させます（`0` も同様）。
> - **WebGL ビルドには WebAssembly SIMD が必須です。** ランタイムは WebAssembly SIMD 命令を使用してビルドされており、SIMD 非対応のブラウザでは動作しません。WebGL で配信する場合はブラウザ要件として扱ってください。
