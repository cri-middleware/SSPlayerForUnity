# SpriteStudioPlayer for Unity — AI Agent Guide

## Operating rules

*   Keep changes scoped to the requested task.
*   Do not commit, push, or open PRs unless the user explicitly asks.
*   Before editing, read enough surrounding context to understand callers and invariants.
*   Follow the existing code style of the file you touch (naming, C# conventions).
*   **Dependencies:** only standard Unity packages (Burst, Mathematics, Collections, Timeline). Do not add third-party packages.
*   **SDK alignment:** when changing core playback, check `SpriteStudio-SDK/AGENTS.md` for Rust-runtime constraints.

## Architecture

A Unity integration for SpriteStudio 7, built for performance. A thin C# "Body" drives the Rust "Brain"
(`libssruntime`) over zero-cost FFI generated by csbindgen. Per-frame geometry is built with Burst jobs and
uploaded to a `Mesh` via `SetVertexBufferData` (zero-allocation). `.sspj` projects are converted to FlatBuffers
(`.ssab`) at import time by `libssconverter`, invoked from a Unity `ScriptedImporter`.

## Hard constraints

*   **FFI safety:** native handles (`SsPlayerHandle`) are `IDisposable`; always call `JobHandle.Complete()` before freeing native resources, or a running Burst job segfaults.
*   **Zero allocation:** the Tick / mesh-update loop must not allocate GC memory. Reuse `NativeArray`; update meshes via `SetVertexBufferData`.
*   **Canvas rebuild bypass:** `SpriteStudioGraphic` (uGUI) overrides `OnPopulateMesh` and the vertex/material dirty flags so Unity does not destroy and reallocate canvas meshes.
*   **Geometry-builder separation:** `SpriteStudioInternalPlayer` owns the native lifecycle, FFI calls, and `IDisposable`; all per-frame geometry (frame-data decode, effect/instance/mask batching, Burst scheduling, mesh upload) lives in `SpriteStudioGeometryBuilder`, its collaborators, and `SpriteStudioMeshJob`. Add rendering features there rather than in the player, and preserve the struct layouts required for Burst and FFI.
*   **Update-loop consistency:** components are batch-updated by `SpriteStudioUpdateManager`. Iterate the snapshotted `_tickCount`, not the live list, so dynamic instantiate/destroy cannot cause a `NullReferenceException`.
*   **Testing:** when changing core logic or the geometry builder, keep the tests in `package/Tests/` green.
